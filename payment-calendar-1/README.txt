ЧАСТЬ 1. НАСТРОЙКА FIREBASE (один раз, займёт 10–15 минут)
============================================================
Firebase — бесплатный облачный сервис Google. Он будет хранить ваши
данные и обрабатывать вход по логину/паролю. Свой сервер не нужен.
Бесплатного плана (Spark) с большим запасом хватает для работы
небольшой команды.

Шаг 1. Создайте проект
-----------------------
1. Откройте https://console.firebase.google.com
2. Войдите под своим Google-аккаунтом (или создайте его)
3. «Add project» / «Создать проект» → введите название, например
   payment-calendar → далее можно отключить Google Analytics
   (не нужен) → «Создать проект»

Шаг 2. Включите вход по email и паролю
----------------------------------------
1. В меню слева: Build → Authentication → «Get started»
2. Вкладка «Sign-in method» → выберите «Email/Password» → включите
   первый переключатель → «Save»

Шаг 3. Создайте базу данных Firestore
----------------------------------------
1. В меню слева: Build → Firestore Database → «Create database»
2. Выберите «Production mode» (боевой режим) → выберите ближайший
   регион (например, europe-west) → «Enable»/«Включить»

Шаг 4. Получите данные для подключения (firebaseConfig)
-----------------------------------------------------------
1. Нажмите на шестерёнку рядом с «Project Overview» → «Project
   settings» (Настройки проекта)
2. Прокрутите вниз до «Your apps» / «Ваши приложения» → нажмите
   значок «</>» (Web) → введите название (например,
   payment-calendar) → «Register app»
3. Появится блок кода с объектом firebaseConfig — скопируйте из
   него значения apiKey, authDomain, projectId, storageBucket,
   messagingSenderId, appId
4. Откройте файл js/firebase-config.js и вставьте свои значения
   вместо «ВАШ_API_KEY» и т.д. Сохраните файл.

Шаг 5. Настройте правила безопасности Firestore
----------------------------------------------------
Это ключевой шаг — без него данные либо будут закрыты для всех
(включая вас), либо, наоборот, открыты кому угодно.

1. Firestore Database → вкладка «Rules» / «Правила»
2. Полностью замените содержимое на текст ниже и нажмите «Publish»
   / «Опубликовать»:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isMember() {
      return request.auth != null &&
        exists(/databases/$(database)/documents/users/$(request.auth.uid));
    }
    function isAdmin() {
      return isMember() &&
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }

    match /users/{uid} {
      allow read: if request.auth != null && (request.auth.uid == uid || isAdmin());
      allow write: if isAdmin();
    }
    match /contragents/{doc} {
      allow read: if isMember();
      allow write: if isAdmin();
    }
    match /payments/{doc} {
      allow read: if isMember();
      allow write: if isAdmin();
    }
    match /settings/{doc} {
      allow read: if isMember();
      allow write: if isAdmin();
    }
  }
}

Смысл этих правил: читать и писать данные может только тот, у кого
есть запись в коллекции users (то есть кого вы сами туда добавили).
Изменять что-либо (платежи, контрагентов, других пользователей)
может только роль admin. Простой email/пароль от Firebase сам по
себе доступа не даёт — обязательно нужна запись в users (следующий
шаг).

Шаг 6. Создайте первого администратора (вручную, один раз)
----------------------------------------------------------------
1. Authentication → вкладка «Users» → «Add user» → введите свой
   email и пароль → «Add user»
2. Скопируйте появившийся «User UID» (длинная строка из букв и цифр)
3. Firestore Database → «Data» → «Start collection» → Collection ID:
   users → «Next»
4. Document ID: вставьте скопированный UID (не «Auto-ID»!)
5. Добавьте поля:
     displayName  (string) — например, Администратор
     email        (string) — тот же email, что при создании
     role         (string) — admin
6. «Save»

Готово. Теперь откройте сайт и войдите под этим email и паролем —
вы администратор.

Все следующие пользователи (сотрудники) добавляются уже прямо из
приложения — кнопка «Пользователи» в шапке (виден только
администратору). Вручную через консоль Firebase их создавать больше
не нужно.


ЧАСТЬ 2. КАК ЭТО РАБОТАЕТ
============================
• Все платежи, контрагенты и настройки хранятся в облаке (Firestore)
  и обновляются на экране всех устройств почти мгновенно — без
  обновления страницы.
• Роли: администратор — полный доступ (добавление/удаление
  контрагентов и платежей, отметка оплаты, управление пользователями).
  Просмотр — видит календарь и суммы, ничего не меняет.
• Автоперенос: неоплаченный платёж на просроченную дату сам
  переезжает на сегодня с красной подсветкой. Проверка выполняется,
  когда в приложение заходит администратор.
• Тема (тёмная/светлая, кнопка ☀️/🌙) — личная настройка каждого
  устройства/браузера, не синхронизируется специально, чтобы каждый
  мог настроить под себя.

Управление пользователями (кнопка «Пользователи», только у админа):
• «Добавить» — создаёт нового пользователя с именем, email, ролью и
  временным паролем.
• «Сбросить пароль» — присылает пользователю на почту ссылку для
  самостоятельной установки нового пароля (безопасный стандартный
  способ; администратор технически не может задать чужой пароль
  напрямую без более сложной серверной настройки — это ограничение
  всех подобных приложений без собственного backend-сервера).
• «Отозвать доступ» — пользователь больше не сможет ничего увидеть
  или изменить в приложении. Сама учётная запись в Firebase при этом
  формально остаётся (просто без прав) — если нужно удалить её
  полностью, это делается вручную: Firebase Console → Authentication
  → находите пользователя → «Delete user».


ЧАСТЬ 3. РАЗМЕЩЕНИЕ НА GITHUB PAGES (или любом другом хостинге)
====================================================================
1. Загрузите всю папку payment-calendar в репозиторий на GitHub
2. Settings → Pages → Source: выберите ветку и папку → Save
3. Откройте выданную ссылку — сайт будет работать одинаково с
   любого устройства, и данные будут общими для всех, кто под своим
   логином туда заходит.

Отдельный сервер, PHP, база данных на вашей стороне — не нужны:
всё уже делает Firebase.


СТОИМОСТЬ
-----------
Бесплатный план Firebase (Spark) включает до 50 000 чтений и 20 000
записей в базу данных в сутки — для небольшой команды (десятки
платежей в день) это более чем достаточно и, скорее всего,
никогда не потребует перехода на платный план.
